air-gapped-signer path, so this is not a clean bill of health. Exploitability against
Keystone's specific call paths was not tested — this is static advisory review only.

## Recommended actions

1. **No dependency change needed this week.** Zero critical, zero high, zero moderate.
   `npm audit fix` has nothing safe to do — every remaining finding reports
   `fixAvailable: false`.
2. **Accept the `elliptic` residual, now scoped to Keystone alone.** Revisit only if
   Keystone ships a `hdkey`/`secp256k1`-free release, or if the advisory is upgraded
   above low. Do not downgrade the SDK to chase it.
3. **Treat the `@noble`/`@scure` 2.x line as a reviewed cryptography change, not a
   routine bump.** Six packages, four of them major, all on the seed/derivation/signing
   path. They carry no advisory, so there is no security pressure to move — schedule
   them deliberately with their own compatibility tests, not via a grouped Dependabot PR.
   Note that `dependabot.yml`/CODEOWNERS already split these out (H-4, PR #1436); that
   split is doing its job and should stay.
4. **Refresh the lockfile at some point to pick up `@capacitor/core` 8.5.0** within the
   existing `^8.4.2` range. Not urgent — no advisory.

## Method note

The first pass of this scan ran in the primary shared checkout and reported **37**
(20 low, 17 moderate) — including
[GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq) (`uuid` <11.1.1,
moderate) and the `@ethersproject/*` v5 chain. **That number is not `main`** and is not
reported as a finding here. It was discarded and the scan re-run from a clean worktree.

Why it differed, stated precisely, because the first draft of this note got it wrong:
the primary checkout sits on `codex/2-biometric-security-center`, which is 121 commits
behind `origin/main` and predates `6e8b3bef` (#2032, the Ledger/Trezor removal). That
branch therefore still carries those SDKs in its **committed** `package.json`. Nothing is
re-adding them — the branch simply never had the removal. Its uncommitted edits are
unrelated to hardware wallets (they add `appium-xcuitest-driver` and a `deepmerge-ts`
override). Rebasing onto `main` drops the 32 extra advisories on its own; no dependency
work is needed there.

The general lesson is the one already in `CLAUDE.md`: read from the ref, not the tree.
`npm audit` resolves from whatever `package-lock.json` is on disk, so running it in the
shared checkout measures whichever branch that checkout happens to be on. Run it in a
worktree cut from `origin/main`, or the headline number is unattributable.
