## Moderate / Low (summary)

### Moderate — Keystone SDK / `uuid`

All 17 moderate entries stem from [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq): `uuid` releases below `11.1.1` can miss a buffer bounds check in v3/v5/v6 when a caller supplies `buf`.

- `@keystonehq/keystone-sdk` is a direct **production** dependency; npm reports it as
  affected through `uuid` and 15 `@keystonehq/bc-ur-registry-*` packages.
- The 15 registry entries are transitive production dependencies. `bc-ur-registry-eth`
  is additionally affected through `hdkey`.
- All affected entries report `fixAvailable: false`; no automatic fix was attempted.

This is a static advisory match, not a demonstrated vulnerable call path. The scan has
not established whether Keystone or its registry dependencies call the affected `uuid`
APIs with an undersized buffer. Treat it as third-party production supply-chain exposure,
not as a demonstrated Veyrnox wallet-crypto defect.

### Low — vendor cryptography dependencies

The remaining 20 low entries include [GHSA-848j-6mx2-7j84](https://github.com/advisories/GHSA-848j-6mx2-7j84) for `elliptic <=6.6.1` (installed `6.6.1`), reached through two vendor SDK families:

- Ledger: direct `@ledgerhq/hw-app-eth` → vendored ethers v5 packages → `elliptic`.
  npm's suggested `@ledgerhq/hw-app-eth@6.40.3` is a major **downgrade** from the
  installed 7.8.14 and is declined.
- Trezor: direct `@trezor/connect-web` → `@trezor/utxo-lib` → `tiny-secp256k1` /
  `elliptic`, with related `crypto-browserify` entries. No fix is available.

Veyrnox's own signing and derivation stack uses `@noble`/`@scure`; neither appears in the
audit. The vendor libraries remain meaningful production dependency surface, so this is
not a clean bill of health. Exploitability against their specific call paths was not tested.

## Recommended actions

1. **Do not run `npm audit fix` or `--force`.** The automatic-fix gate is not met, and
   npm proposes major downgrades for the HIGH WebdriverIO and Ledger paths rather than a
   safe forward remedy.
2. **Triage the Keystone `uuid` advisory with its upstream.** Confirm whether the
   affected v3/v5/v6-with-`buf` paths are reachable before considering a manual override
   or SDK upgrade; `fixAvailable: false` means this scan has no safe automated change.
3. **Track a forward WebdriverIO release using `deepmerge-ts >=8`.** Keep the current
   e2e stack rather than downgrading it to 7.x.
4. **Keep tracking Ledger/Trezor's `elliptic` dependency.** Revisit only with a forward
   vendor fix; do not downgrade their SDKs.
5. **Schedule the listed native/build patch updates normally.** Treat noble/scure 2.x
   moves as separate, reviewed cryptography changes with their own compatibility tests.
