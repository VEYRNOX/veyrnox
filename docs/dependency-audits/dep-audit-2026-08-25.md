## Moderate / Low

All 5 findings are **low** and every one traces to a single root advisory with no fix
available at any version:

- [GHSA-848j-6mx2-7j84](https://github.com/advisories/GHSA-848j-6mx2-7j84) —
  `elliptic`, "Uses a Cryptographic Primitive with a Risky Implementation".

`npm audit --json` reports exactly five advisory entries, which are the root plus its four
transitive dependents:

One path, unchanged:

```
@keystonehq/keystone-sdk 0.12.3 (direct)
  └─ @keystonehq/bc-ur-registry-eth 0.22.1 (direct)
       └─ hdkey 2.1.0
            └─ secp256k1 4.0.5
                 └─ elliptic 6.6.1
```

The `via`/`effects` graph npm builds reproduces these four edges independently of the
lockfile walk in the residual entry, so the two derivations agree.

**No upstream escape hatch exists for this chain.** Every link is already at its newest
published version (`keystone-sdk` 0.12.3, `bc-ur-registry-eth` 0.22.1, `hdkey` 2.1.0 all
`latest`), and `secp256k1@latest` is `5.0.2` — a major ahead of the resolved 4.0.5 — which
*still* declares `elliptic ^6.5.7`. This is the opposite of the retired Trezor path, where
`tiny-secp256k1@2.x` had already dropped `elliptic` upstream and only a parent pin had to
move. Short of a patched `elliptic`, clearing this requires a package that does not exist
yet.

returned 1,111,015 and the extracted file matched that byte count exactly. A silent
`MSYS_NO_PATHCONV` failure yields an empty file that audits as zero vulnerabilities, so
that check is what separates a real all-clear from a broken command.
