### `src/pages/PersonalBackup.jsx:802-809,1191-1203,1223` — NEEDS-REVIEW (decoy session is now distinguishable on the Advanced tab)
**Commits:** 7374231a fix(backup): preserve existing share recovery after expiry (#2792);
1628ddea branch-review fixes (#2835)
**Change summary:** `RecoveryShareTab` is no longer rendered only for Safety Plus. It now renders
on every tier so a lapsed subscriber can still restore legacy same-device shares; creating new
shares stays paid.
**Assessment:** The tier gate itself is sound. I read the component in full on `origin/main`:
- Export is blocked three ways when `canCreate` is false: `canExport` (`:812`), an early return
  in `runSplit` (`:815`), and the export form is never rendered (`:970`). `canCreate` is
  `!tierLoading && hasSafetyPlus`, so it is false while the tier is unknown (fail closed).
- Restore keeps both RASP checks (`sensitiveGate` plus the fresh-at-confirm probe), the PIN
  strength and confirm checks, and zeroes unwrapped share bytes in `finally`.
- Internal error codes are now mapped to sentences; unknown codes get a generic message, so no
  identifier or stack reaches the user.

The open item is a side effect on deniability. `TierProvider.jsx:118-121` forces the tier to
`free` in a decoy or hidden session. Before this window a decoy session on Backup → Advanced
therefore showed only the Safety Plus upsell card, exactly what a real free-tier session showed.
Now the tab renders for every tier, and its first branch (`:802`) returns "Recovery shares are
unavailable in this session." for `isDecoy || isHidden`. So:

| Session | Advanced (2-of-3) tab on `origin/main` |
|---|---|
| Real, free tier | Export/Restore toggle, restore form, upsell card with the "existing recovery material" note |
| Decoy or hidden | "Recovery shares are unavailable in this session." banner, upsell card **without** that note (`:1223`) |

No real session ever shows that banner. Someone holding the unlocked phone who knows the app
can open this tab and tell a decoy from a real free wallet. Before the window the string was
unreachable in a running app, because the tab needed Safety Plus and a decoy is always free.
The existing decoy test (`PersonalBackup.recovery-shares.test.jsx:134`) passes because it mocks
`isDecoy: true` together with the default `tier = 'safety_plus'`, a combination the app cannot
produce.

This is not an I3 violation in the strict sense (no backend call is made), and no key material
is exposed. It is a coercion-resistance gap in a wallet whose design rule is "deniability by
default". Inferred from source; not exercised on a device (a simulator cannot run a decoy
session). It shipped to production in OTA bundle `202610031506`.

**Recommended fix (not applied; read-only task):** make the decoy and hidden branch render what
a real free-tier session renders with no usable shares (the same toggle and note, with restore
failing the way a wrong share set fails), or go back to the upsell-only view for both. Add a
test that mounts the page with `isDecoy: true` and `currentTier: 'free'` and asserts the DOM
matches the real free-tier render.
