### `src/risk/calldata.js` — SAFE (security control added)
**Commit:** `2ef5f681` fix(risk): fail closed on multicall- and permit-wrapped approvals (#2739) (#2740)
**Change summary:** `classifyApprove()` was a flat 4-selector allowlist (approve, increaseAllowance, setApprovalForAll, Permit2 approve). Two drain-enabling calldata shapes fell outside it and returned `{ isApprove: false }`: an unlimited `approve()` wrapped in `multicall([...])`, and an EIP-2612/DAI `permit()` submitted as calldata (grants allowance with no on-chain `approve()`). Either shape made S2/S3 answer OK ("Not an approval") — a green confirm screen for a drain. Adds `OPAQUE_APPROVAL_KINDS` recognising the multicall and permit selector families and returns `{ isApprove: true, decoded: false, kind: 'wrappedCall'|'permit' }` for them, rather than decoding the nested calldata (correctly out of scope — the file's pure/no-network contract).
**Assessment:** This is I4 (fail honest, fail closed) done correctly: the fix does not try to prove the wrapped call safe, it reports it as undecodable so downstream signals fail to INDETERMINATE instead of OK. Verified downstream: `s2UnlimitedApproval`/`s3FreshSpenderApproval` were checked directly (see test below) and now return INDETERMINATE, never OK, for both shapes. No control was removed; a real gap was closed.
