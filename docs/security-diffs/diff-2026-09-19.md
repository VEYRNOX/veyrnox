### `android/app/src/main/java/com/veyrnox/app/OtaBundleVerifier.kt`, `ios/App/App/VeyrnoxOta.swift`, `scripts/ota/release.mjs`, `src/lib/otaUpdate.js` — NEEDS-REVIEW

**Commit:** `64c61512` feat(ota): pin two hardware signing keys, accept either

**Change summary:** Android and iOS now pin two non-empty P-256 public keys and accept a manifest signed by either. The release utility can convert a PKCS#11 raw ECDSA signature to DER and refuses to persist it unless it verifies under a pinned key. Native and JavaScript regression tests cover empty lists, either pinned signer, unpinned rejection, DER conversion, and parity of the two native key lists.

**Assessment:** The multi-key verification change is fail-closed at source level: an empty list disables OTA, a signature must verify under at least one pinned key, and the stored bundle remains subject to manifest, hash, version, channel, and native-API checks. The change also makes OTA capable of becoming active in the next store binary: every `vite build` embeds `ota-manifest.json`; when that binary contains a non-empty key list, `startOtaUpdate()` calls the native `status()` and then fetches `https://updates.veyrnox.com/<channel>/latest.json` before unlock. That request occurs before real, decoy, hidden, or demo session state is known.

This is the exact deployment-gated I3 issue raised in the 2026-09-15 report, now materially closer to activation. The source comments say that equal request patterns across session types preserve deniability, but the repository invariant is stricter: deniability mode means zero backend calls. `docs/ota-updates.md` says no store release carrying the keys has shipped and nothing has been published to the update host, so this scan does **not** claim a current live request or a deployed regression. Before shipping a keyed native build, obtain and record owner approval for this pre-unlock egress (or redesign it so the I3 condition holds), update the user-facing privacy disclosure, and perform real-device verification. This is INTERNAL static analysis only; the key provisioning and OTA flow are not device-verified or independently audited.
