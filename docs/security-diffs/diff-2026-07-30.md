### src/i18n/index.js:81 `MACHINE_TRANSLATED` — NEEDS-REVIEW
**Commit:** `d4eaf593` feat(i18n): drop MT-pending banner for es, es-419, pt-BR, fr, it (#1507)
**Change summary:** Flips `MACHINE_TRANSLATED` from `true` to `false` for 5
locales, on the strength of a native-speaker review pass. Dropping the flag
removes the "machine translated, not reviewed" banner for that locale.

**Assessment:** The review covered ONE of three namespaces; the flag it clears
covers all three.

The banner text is an explicit claim to the user:

> "This translation was generated by machine and has not been reviewed by a
> native speaker. If any wording looks wrong, switch back to English until it
> is reviewed."

Scope of the review, from the commit's own evidence — all 5 archived patch
files under `docs/i18n-review-patches/` carry `"namespace": "security"`, and
the commit message says the reviewer "walked the full security.json catalog":

| namespace | strings (per locale) | reviewed |
|---|---|---|
| `security.json` | ~249 | yes |
| `common.json` | ~50 | no |
| `wallet.json` | ~561 | no |

(Leaf-string counts are a static count of key/string-value pairs; the patch
files self-report `reviewed_count: 256` for `security`. The small delta is a
counting-method artifact and nothing is claimed on it. The namespace scope,
which is what this finding rests on, is unambiguous from the patch files.)

Scope of the flag: `MACHINE_TRANSLATED` is keyed by LOCALE, not by namespace.
`LanguageSwitcher.jsx:31` reads `const isMT = !!MACHINE_TRANSLATED[current]`
and gates the whole banner on it. Confirmed by `git grep` that no
per-namespace MT mechanism exists anywhere in `src/` — the symbol appears in
exactly 4 code positions (2 in LanguageSwitcher, the declaration, and a
comment in `Settings.jsx`).

Net effect: ~611 of ~860 strings per locale (~71%) remain unreviewed machine
translation and no longer carry any disclaimer. Across the 5 locales that is
~3,055 strings.

This matters because `wallet.json` is not cosmetic copy. Reading the French
catalog directly, the un-reviewed, now-undisclosed namespace includes:

- `security.biometric.confirm_disclosure` — a backup-exposure RISK
  ACKNOWLEDGEMENT gating the one-gesture-unlock opt-in: *"Si quelqu'un obtient
  une copie de la sauvegarde de ton appareil sans l'appareil physique, il
  pourrait acceder a ton portefeuille. N'active ceci que si tu es d'accord
  avec ce risque."*
- `settings.reset.confirm_prompt_pre` — account-reset / wipe confirmation copy.
- Biometric and passkey verification status strings.

Run 1 itself recorded that `SendCrypto.jsx` pulls from BOTH the `wallet` and
`security` namespaces, so the send path renders unreviewed copy too.

The implicit premise — "`security.json` is where the security-critical copy
lives, so reviewing it is sufficient to drop the locale's banner" — does not
hold against the catalog contents.

**This is an I4 honesty finding, not a code vulnerability.** No gate is
bypassed and nothing fails open. What changed is the accuracy of a disclosure
the app makes to the user. Worth stating plainly: the commit message is
candid in other respects — it volunteers the ~3.5 second/string review pace
and explicitly says the signoff does not mean "perfect translation". This
reads as a flag-granularity oversight, not an attempt to overstate.

**Options for the owner (no change made — this task is read-only):**
1. Make the MT flag per-namespace (`{ security: false, wallet: true, ... }`)
   and have the banner reflect what is actually reviewed. Highest fidelity.
2. Extend the review to `wallet.json` + `common.json` for these 5 locales
   before dropping the flag.
3. Revert the 5 flags to `true` until 1 or 2 lands.
