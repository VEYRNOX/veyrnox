### `package.json` / `package-lock.json` — `hash-wasm` ^4.12.0 → ^4.13.0 — NEEDS-REVIEW
**Commit:** `10bf54b0` (#2970, 24-package npm-minor-patch group)
**Change summary:** `hash-wasm` is the Argon2id implementation behind `src/wallet-core/vault.js` (`import { argon2id } from 'hash-wasm'`). Its 4.13.0 changelog (read from the published tarball) says all 22 WASM modules were **rebuilt** on a new toolchain (Alpine 3.20.3→3.24.4, Clang/LLD 17→22), so the shipped `argon2` binary is not the one that was exercised before. Other 4.13.0 changes are bcrypt zero-byte handling (the repo does not use bcrypt for the vault), typings and dev tooling.
**Assessment:** A KDF binary that produced even one different output for the same password, salt and parameters would make existing vaults fail to unlock, and that failure is silent until a real unlock. I did **not** run a known-answer comparison of 4.12.0 against 4.13.0. An attempt to execute the downloaded package was refused by the harness, so the check is untested, not passed. A lockfile `integrity` for 4.13.0 is present and resolves to `registry.npmjs.org`. The caret range is also unlike the repo rule to pin crypto/security packages exactly (the `@noble/*`, `@scure/*` and `ethers` pins are untouched). The range was already caret before this change.
Next step for a human: confirm a fixed-vector Argon2id test against an **existing** vault blob ran green in CI on `10bf54b0`. A mismatch would not show up in tests that only derive and re-derive with the same build. Consider pinning `hash-wasm` exactly.
