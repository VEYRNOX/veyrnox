### src/wallet-core/assets.js + src/wallet-core/evm/tokens.js — SAFE (evidence caveats below)
**Commit:** 08d434ff
**Change summary:** Four new registry rows (`LINK`, `UNI`, `SHIB`, `LEO`, all `RECEIVE_ONLY`, `erc20`, `mainnet`) and four pinned Ethereum-mainnet contract entries (18 decimals each). New exported count constants derived from the registry.
**Assessment:**
- This is the first time REAL mainnet addresses sit behind the receive-only boundary. I re-read the three boundaries from `origin/main`:
  - `sendToken` (`token-send.js`): resolves the asset by `assetId`, and `!canSend(asset)` throws `Token … is not LIVE` before provider construction or key use. The only bypass is a vite DEV build + `VITE_DEV_UNGATE_SEND=1` + a testnet network, which cannot apply to mainnet.
  - WalletConnect (`WalletConnectProvider.jsx:~615-630`): any `eth_sendTransaction` whose `to` matches a registry token on the request's chain is rejected with `WC_TOKEN_NOT_LIVE` before the 2FA check and before `withPrivateKey`, for every selector. The test now drives it with the real mainnet addresses for all four symbols and asserts `withPrivateKey` is never called.
  - `canSend` is pinned false for exactly `['LINK','UNI','SHIB','LEO']` in `send-gate-harness-a.test.js`, so a fifth receive-only row or a flip to LIVE changes a test.
- Address spot-check: the four checksummed addresses match the ones I know for these tokens (static recall, not an on-chain read; this task cannot query a chain). Per the file's own comments, SHIB rests on weaker evidence (an SDK code example, no issuer listing), and LEO's pause/blacklist behaviour is only heuristically probed, not reviewed from source. Both are honestly recorded in the code and `Feature-Status.md`. A wrong address would cause misleading balance reads, not an unauthorised send, because sends are gated off.
- Residual by design: only calls aimed directly at the token contract are blocked. A connected dApp or router that already holds an approval can still move these tokens. The PR adds the mandated copy ("Direct sends are disabled. Connected dApps may still spend this token through existing approvals.") on every asset-count surface.
