### `workers/referral-redirect/src/index.js:26-47` — SAFE (resolves 2026-09-12 addendum low NEEDS-REVIEW in source)
**Commit:** `7e61d42b` `fix(referrals): Worker /r/ path match follows live Pages routing (#2534)` (merged via `60423c74`)

**Change summary:** The Worker used to rebuild `params.code` with
`split('/').filter(Boolean)`. It now matches the path against an exported
`PATH_RE = /^\/r\/([^/]+)\/?$/`. On a non-match it passes `[]`, which the Pages
function treats as "not a referral link". `src/lib/referralAttribution.js` already
used the same regex literal for the native reader. It gains only a comment. A new
test checks that the native file contains the Worker's exact literal.

**Assessment:** This fixes the finding the addendum raised. `filter(Boolean)`
collapsed empty path segments, so the Worker accepted `/r//CODE` and `/r/CODE//` as
referral links, and the other two readers did not. The commit message says the
Pages routing rule was measured on the live host. According to that message, Pages
accepts one trailing slash and rejects doubled slashes. That differs from the
addendum's table, which said Pages fails closed on `/r/VYX-STRKLB/`. The author
therefore left native alone and moved the Worker onto native's rule. I did not
repeat the live measurement, so the Pages side of the table is the author's
evidence, not mine.

I checked the change by running the code, not just by reading it. I extracted the
`origin/main` Worker (with the AASA import stubbed), the unchanged
`functions/r/[code].js`, and the native `referralCodeFromUrl`, and ran them over
these paths:

| path | Worker `Location` | native |
|---|---|---|
| `/r/VYX-STRKLB` | `…/?ref=VYX-STRKLB` | `VYX-STRKLB` |
| `/r/VYX-STRKLB/` | `…/?ref=VYX-STRKLB` | `VYX-STRKLB` |
| `/r//VYX-STRKLB` | `…/` | `null` |
| `/r/VYX-STRKLB//` | `…/` | `null` |
| `/r/VYX-STRKLB/extra` | `…/` | `null` |
| `/r/`, `/r`, `/R/VYX-STRKLB` | `…/` | `null` |
| `/r/%2F%2Fevil.com` | `…/` | `null` |
| `/r/VYX-STRKLB%2F` | `…/` | `null` |
| `/r/VYX-STRKLB%0d%0aX:1` | `…/` | `null` |
| `/r/VYX-%E0%A4%A` (bad escape) | `…/` | `null` |
| `/r/vyx-strklb`, `/r/%20VYX-STRKLB%20` | `…/?ref=VYX-STRKLB` | `VYX-STRKLB` |
| `/r/./VYX-STRKLB`, `/r/x/../VYX-STRKLB` | `…/?ref=VYX-STRKLB` | `VYX-STRKLB` |

The Worker and native now agree on every path tested. Every response is a `302` to
the fixed origin `https://veyrnox-prod.pages.dev`, with `Cache-Control: no-store`
and `Referrer-Policy: no-referrer`. An encoded slash, a CRLF, or a protocol-relative
payload all fall back to the app root. The last two rows are URL normalisation:
`new URL()` resolves dot segments before matching. They still have to pass
`CODE_RE`, so they are not an exploit. I did not check whether Pages routing
normalises dot segments the same way.

This change touches no key material, signing, gate, or secret, and adds no binding
or egress. Since the path now has to match one of two regexes, the Worker is
strictly tighter than before.
