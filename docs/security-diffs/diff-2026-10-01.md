### `src/lib/safetyPlusRoutes.js`, `src/pages/DuressPin.jsx`, `src/pages/PersonalBackup.jsx` — SAFE
**Commit:** `98d3ff3b` feat(paywall): cancellation assurance, tier comparison, recovery gating fix (#2781)
**Change summary:** `/duress-pin` and `/personal-backup` are removed from `SAFETY_PLUS_ROUTES`
(the route-level gate that replaces the *entire page* with a paywall) and moved to a new
`SAFETY_PLUS_PAGE_GATED_ROUTES` list that is classification-only. In-page gating now applies
instead: DuressPin's "Setup card" (create/change PIN) is wrapped in `{hasSafetyPlus && (...)}`
with an upsell card shown otherwise, while PIN *removal* and the rest of the page render
unconditionally. PersonalBackup's "Create backup" / "Advanced (2-of-3)" tabs are gated the same
way; "Restore" is never gated.
**Assessment:** This is a genuine fix, not a weakening. Previously a lapsed Safety Plus
subscriber hit a full-page paywall on these routes and could not remove an Emergency PIN or
restore from an existing backup — a real I4/safety concern (a user locked out of disabling
their own duress mechanism). The new shape gates *creation* only; the setup-card UI (and its
`setDuressPin`/`removeDuressPin` handlers) is unmounted entirely when ungated, not just
visually hidden, so there's no exposed call path for a free-tier user to create a new PIN via
the hidden form. Confirmed by direct read of both files (not grep) and by
`src/lib/__tests__/safetyPlusRoutes.test.js` + `src/lib/__tests__/tier.featureRouteParity.test.js`,
which pin `isSafetyPlusRoute('/duress-pin') === false` and maintain a bidirectional map from
every paid feature name to its gating route(s) — the test file's own comments document two
prior real drift incidents this map was built to catch (advertised-but-ungated and
gated-but-unadvertised).
