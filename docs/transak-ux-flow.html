3 · Controls annotated in the flow

  • I3 render gate — isDeniabilityOrDemoActive() hides every Buy entry point in decoy/hidden/demo sessions; the URL builder throws BUY_DENIABILITY_BLOCKED even if a caller bypasses the render check (two-chokepoint pattern).
  • I5 address correctness — deposit address is read from the on-device wallet AT PRESS-TIME, not at mount, not from a cached value, not from a URL param. Wrong network → hard error rather than send-to-unusable-address.
  • System browser, not in-app WebView — Transak's KYC session, cookies and analytics run in a browser context separate from the wallet process. Transak's data collection is not attributed to the Veyrnox app.
  • Universal Link return — https://veyrnox.com/buy/return (not a custom veyrnox:// scheme). Apple/Google-blessed; survives Chrome's custom-scheme stripping.
  • Return payload not trusted — /buy/in-progress shows a neutral status; funds are confirmed only by on-chain observation of the deposit address (I5, backend untrusted).
  • Ship gate — VITE_BUY_ENABLED defaults to false; the Buy tiles are dead-code-eliminated from production builds until Transak's partner agreement + production API keys are in place.
